# 面向转弯误差的控制器研究设计

本目录实现“曲率预瞄追踪器引导的执行链感知残差 MPPI”研究原型：追踪器给出可解释的基础动作，采样优化器调整残差，并在预测中考虑速度平滑器、命令排队延迟和一阶执行滞后。目标是减少入弯滞后与出弯过修。

**当前交付范围按用户最新要求限定为巡检轨迹跟踪，不考虑避障。** 巡检入口的障碍集合为空；早期可选障碍分支和试验保留为开发记录，不进入本轮验收。

**当前没有完成新控制器在原 FAST-LIO＋NDT 定位链上的实车闭环对比。** 冻结旧配置及其哈希只能证明配置来源；历史 NDT 轨迹只能诊断旧算法表现；离线仿真只能验证所设模型中的行为。这三类证据不能互相替代。本文件不填写实验成绩。

## 为什么从执行链入手

本机正式链见 [ARCHITECTURE.md](../../ARCHITECTURE.md) 和 [控制链审计](../../docs/controller_tracking/CONTROL_CHAIN_AUDIT.md)。`navigation.yaml` 中有两个原生 MPPI 插件，必须在每轮报告中明确选择：

| 配置事实 | 对研究的含义 |
|---|---|
| `FollowPath.wz_max=0.65`，平滑器最大角速度为 `0.45 rad/s` | 内部预测可能采用执行器不会实现的曲率；需单独做约束匹配对照 |
| `InspectionStrict.wz_max=0.45`，已使用路径切线和较高跟踪权重 | 不能把所有误差都归因于角速度上限，也不能把增加权重当作主要创新 |
| 下游为 `OPEN_LOOP` 平滑器，线、角速度分别限制，`scale_velocities=false` | 过渡阶段实际曲率可能不同于原动作的比值 |
| 已安装 MPPI 为 Nav2 `1.1.20` | 该版本官方参数读取与模型没有实现 YAML 中所写的 `ax_max/az_max` 等内部加速度约束；不能依据注释认定它们生效 |
| 上层使用 DiffDrive，底盘实际经过舵轮逆解、舵角滤波与内部限速 | 舵向建立过程值得辨识；现阶段不能宣称某个滞后值是实测结果 |

版本依据为官方 [1.1.20 优化器](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_mppi_controller/src/optimizer.cpp)、[运动模型](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_mppi_controller/include/nav2_mppi_controller/motion_models.hpp) 和 [速度平滑器](https://raw.githubusercontent.com/ros-navigation/navigation2/1.1.20/nav2_velocity_smoother/src/velocity_smoother.cpp)。版本结论只适用于上述原版本，不能推广到当前 Nav2 所有版本。

## 原型如何工作

设左侧横向误差为正，航向误差为车体航向减去路径切线航向。基础角速度采用曲率前馈与横向、航向反馈；执行链模式另外按命令延迟预瞄曲率，并用曲率变化率近似补偿一阶角速度滞后。末段减速与角速度可达性限制属于基础行为，不能单独作为创新成绩。

采样变量是基础动作周围的线、角速度残差。保留确定性追踪候选、上一轮残差、左右探索和减速候选，以降低有限样本完全错过可用动作的概率。每条预测轨迹都经过相同的速度限制、加速度限制、延迟队列和执行动态，然后计算跟踪、进度、动作与障碍代价。

障碍在当前软件场景中表示为圆，车体表示为带原配置膨胀的矩形；矩形与圆的有符号距离用于筛选。加权平均残差重新预测，通过可行性检查才可采用，否则退回可行候选。无可行候选时输出零目标动作并记录失败；既有运动与延迟意味着零目标动作并不等于瞬间停车。

这是一个**受 MPPI 启发的引导残差采样预测控制原型**，包含候选筛选、硬约束拒绝和最优候选回退。指数代价权重用于启发式残差更新，没有针对当前状态依赖提议和筛选机制给出新的重要性采样推导。不得声称理论最优性、闭环稳定性、递归可行性或连续时间无碰撞保证。离散预测点的碰撞检查也不能证明真实底盘扫掠安全。

当前模式的解释：

| 模式 | 含义与比较边界 |
|---|---|
| `tracker` | 同一基础追踪器，保留执行模型与可行性筛选，不做残差采样 |
| `ideal` | 残差采样保留，但去掉执行链动态及相应的预瞄/滞后补偿；它是联合去除这些机制的消融 |
| `full` | 执行链感知追踪提议＋残差采样＋最终动作复核 |
| 原生 MPPI 离线适配 | 直接调用已安装原始插件的计算接口；离线内存 costmap 和合成状态不是完整 Nav2 导航或 FAST-LIO＋NDT 闭环 |

`controller.py` 不发布 ROS 运动命令。原生适配器的职责是避免用自行重写的 MPPI 冒充原算法；其离线接口仍须记录插件名、参数来源、状态来源和 costmap 条件。

## 已有研究与可主张的贡献

- [Tube-MPPI，RSS 2018](https://m.roboticsproceedings.org/rss14/p42.pdf) 已结合 MPPI 与辅助追踪控制器。简单串联两类控制器不是新概念。
- [RMPPI，RA-L 2021](https://arxiv.org/abs/2102.09027) 已把低层追踪控制能力纳入采样优化。
- [Smooth MPPI](https://arxiv.org/abs/2112.09988) 已利用输入提升和动作代价改善平滑性。
- [SVG-MPPI](https://arxiv.org/abs/2309.11040) 已研究引导采样与多模态分布，并验证路径跟踪与避障。

本项目的研究假设应收窄为：**在本舵轮平台上，显式预测曲率变化与下游执行链的共同作用，比单独提高路径权重或只匹配速度上限，更能降低转弯阶段误差。** 是否成立由后续消融与实车重复试验决定；当前既不宣称全球首次，也不宣称已经达到论文创新标准。

## 怎样做有说服力的实验

先报告软件场景中的合成闭环结果，明确 plant 参数是研究设定。各方法面对相同 plant、初始状态、路径、障碍和扰动序列；控制器假设与 plant 不应永远完全相同。留出不同的滞后、延迟、速度增益和状态噪声条件，检验模型失配敏感性。当前离线计算耗时被记录，但未反馈成额外的 plant 延迟；计算超期不能忽略，离线几何完成也不等于终点停车或实车实时可用。

后续补齐以下对照，才能区分机制：

1. 冻结的原生 MPPI；分别注明 `FollowPath` 或 `InspectionStrict`。
2. 原生 MPPI 仅做执行约束匹配，检验收益是否只来自修正上限。
3. 纯追踪器及当前带可行性筛选的追踪器，区分控制与筛选作用。
4. 无执行模型与补偿的引导残差采样；进一步分别移除曲率预瞄、执行动态或残差采样。
5. 完整方法。必要时补 Smooth MPPI、RMPPI 或另一种成熟追踪器作为更强对照。

MPPI 类方法应报告相同预测长度、样本数和实际计算预算；若无法同时匹配，分别给出样本匹配与时间匹配结果。所有方法使用相同速度、角速度和加速度约束，并额外采用相同参考速度曲线对照，防止把单纯减速带来的误差降低归因于新控制结构。原生插件关闭障碍代价的旧参数不能作为避障能力的公平基线；避障扩展须单列参数与实验。

路径覆盖左右弯、不同半径、直线入弯/出弯、连续反向 S 弯、曲率快速变化与窄通道。按预先冻结的参考路径几何定义阶段，不能根据测得误差挑选“有效弯道”。报告有符号横向误差、距离误差 RMSE/P95/最大值、航向误差、完成率、耗时、速度、角速度裁剪比例、最小间隙及计算时间分位数；失败轮次保留并进入分母。统计单位应为重复试次，不能把一轮中的高频采样点当独立重复。

## 接入原 FAST-LIO＋NDT 前还缺什么

- 独立辨识平滑器之后的线/角速度响应、有效延迟与左右转差异，冻结辨识集和留出验证集。使用原始位姿源时间与命令接收时间，不能只看被刷新过的 `/odom` header。
- 验证底盘角速度符号、舵轮执行限制与反馈单位。现有审计明确保留了部分单位和真实目标舵角的未知项，不能靠仿真填补。
- 测定定位更新的时间新鲜度、NDT 修正与连续 LIO 的关系；不要在各控制器之间更换定位或重新拟合空间/时间对齐。
- 用独立的动捕或其他测量覆盖实际弯道。已有历史 NDT 轨迹是地图估计偏差，混合定位误差；原有初末停车窗口不能代替全程动态真值。

实车对照须冻结同一原 PCD/地图、FAST-LIO＋NDT 参数、TF 外参、实际下发路径、底盘限值与配置哈希，只替换指定控制器。先做独立试验入口和不发命令的记录核查，再采用相同起点与速度、随机化或交错的控制器试次顺序，逐轮归档完整命令链、定位源时间、跟踪状态与独立真值。保留原手动/停止门控和失败停止逻辑。跟踪与避障分别验证；正式障碍禁用配置不得在报告中被描述为已验证自主避障。

只有上述真实闭环完成，才可以写“使用同一种原 FAST-LIO＋NDT，改进控制器降低了实测转弯误差”。当前结论应限于原型实现、原算法离线调用、历史诊断以及明确模型条件下的软件结果。
